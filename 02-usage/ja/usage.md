# 02 利用方法

本書では、自己評価ツールを用いてベースラインに照らした評価を行う方法を説明する。オンライン、オフライン、私有化デプロイの3つの利用方法、および評価ルールとデータの保存方式を扱う。ツール自体のディレクトリ構成と保守方法については [03 ツール](../../03-tool/docs/ja.md) を参照。

## 評価例

以下のスクリーンショット（英語）は同梱の模擬データから生成したものであり、Teloa や実在するプラットフォームの評価ではない。

![模擬成熟度レポート（英語）：L1 達成、目標 L2、充足率約79％、不足47件](../assets/maturity-report.en.png)

L1 の90件はすべて満たす。L2 で追加される137件は、満たす90件、部分的に満たす20件、満たさない17件、未評価10件。目標内では180 / 227件で、表示は79％。L2 まで47件不足する。L3 の13件は未評価で、目標 L2 の充足率には含めない。

![模擬カバレッジマトリクスの一部（英語）](../assets/coverage-matrix.en.png)

### スクリーンショットを再現する

1. [サンプル評価 JSON](../examples/demo-assessment.json)をダウンロードする。
2. ツールのデータページでファイルをインポートする。現在の評価を置き換えるため、既存データは先に JSON でエクスポートする。
3. 評価レポートで成熟度とグラフを確認し、カバレッジマトリクスで差分を探す。

## 1、3つの利用方法

### 1.1 オンライン

GitHub Pages または Cloudflare Pages に公開できる。どちらも無料プランがあり、手順は第4節を参照。Cloudflare Pages は `03-tool/` 直下の `_headers` を読み込み、nginx の設定と同じセキュリティレスポンスヘッダを付与する。GitHub Pages はカスタムレスポンスヘッダに対応していない。

### 1.2 オフライン

利用方法は2種類ある。

- **オフライン Web ページ**：リポジトリの zip をダウンロードして展開し、`03-tool/index.html` をダブルクリックすれば利用できる。機能はオンライン版と完全に同一である。
- **オフライン Excel**：`03-tool/offline/baseline-assessment.xlsx` に直接入力する。表にはプルダウン選択肢、集計数式、ギャップ統計が含まれ、入力後は Web ページに読み込み直して評価を続けられる。

### 1.3 私有化デプロイ

ページは純粋な静的ファイルであり、任意の静的ファイルサーバでホストできる。リポジトリには非 root ユーザで動作する nginx イメージ用の設定が同梱されており、コンテンツセキュリティポリシーによりページから外部アドレスへの接続を禁止している。

```bash
cd 03-tool && docker build -f deploy/Dockerfile -t agent-baseline-assessor .
docker run -d -p 8080:8080 --read-only --tmpfs /tmp agent-baseline-assessor
```

Docker を使わない場合は、`03-tool/` 直下の `index.html`、`assets/`、`data/`、`vendor/`、`offline/` を Web ルートにコピーすればよい。あわせて `deploy/nginx.conf` のセキュリティレスポンスヘッダを適用することを推奨する。MIME タイプは nginx 付属の `mime.types` をそのまま使い、server ブロックに `types {}` を別途記述してはならない。記述すると表全体が上書きされ、ページがファイルとしてダウンロードされてしまう。

## 2、機能

| 画面 | できること |
| --- | --- |
| カバレッジマトリクス | 上部に現在の達成レベルと L1・L2・L3 各レベルの達成状況を表示する。章別表示では1行に1章、1セルに1節を配置し、セル下部の区分色帯で各要件の状態を1件ずつ示す。「コンポーネント × 章」に切り替えると、実装コンポーネントごとに章別の適合率を示すヒートマップになる。セルをクリックすると要件を1件ずつ評価できる |
| 要件別評価 | 章、コンポーネント、レベル、状態、キーワードで絞り込み、状態を設定し、根拠、担当者、完了予定日を入力する。不適用の節は節単位でまとめて指定できる |
| 評価レポート | まず結論を示す。成熟度の段階、次のレベルまでに不足している要件数、目標範囲内の適合率、ギャップ項目、評価の進捗を表示し、そのうえで優先対応すべき要件を列挙する。グラフには適合率レーダー（章別またはコンポーネント別）、章別成熟度、ギャップ分布があり、いずれも PNG または SVG でダウンロードできる。あわせてコンポーネント別集計表と完全なギャップ一覧を掲載する |
| データ | 評価情報を入力する。JSON または Excel をエクスポートする。JSON またはオフライン Excel をインポートする。前回の結果を読み込んで比較する。現在の評価をクリアする |

エクスポートされる Excel とオフラインテンプレートは構造が同一で、評価表、集計（数式は状態に応じてリアルタイムに再計算され、目標レベルはプルダウンで切り替え可能）、ギャップ一覧、アーキテクチャ視点、説明の5シートで構成される。

## 3、評価ルール

- **適合率** = 充足済み ÷ 適用対象の要件。集計対象は目標レベル内の要件のみとする。一部充足および未評価は、いずれも未充足として扱う。
- **あるレベルの達成**：当該レベル以下のすべての適用要件が充足されている場合に達成とみなす。1件でも不足していれば、次のレベルの手前で止まる。
- **ギャップ項目**：目標レベル内で適用対象であり、かつ未充足の要件。
- **不適用**：プラットフォームが特定の機能を備えていない場合（例：MCP 非対応）、該当する節を節単位で不適用とし、適合率には算入しない。

Web ページと Excel は同一のルールを用いる。Excel で状態を空欄にした場合、またはプルダウン以外の値を入力した場合は、いずれも未評価として扱う。

## 4、公開

### 4.1 GitHub Pages への公開

1. 新規リポジトリを作成し、プロジェクト全体を `main` ブランチにプッシュする。ワークフローは自動的に `03-tool/` に入ってビルドを行う。
2. リポジトリの Settings → Pages → Build and deployment で、Source を **GitHub Actions** に設定する。
3. 以降 `main` にプッシュするたびに、`.github/workflows/pages.yml` がオフライン評価表を再生成し、自己チェックを実行したうえで、ページに必要なファイルのみを公開する。ビルドジョブの権限は読み取りのみで、依存関係のインストール時にインストールスクリプトは実行しない。公開ジョブはサードパーティ製のコードを一切実行しない。

GitHub の無料アカウントで Pages を有効にできるのは公開リポジトリのみである。ベースラインをまだ公開できない場合は、私有化デプロイを利用するか、プライベート Pages に対応した GitHub Enterprise を利用する。

### 4.2 Cloudflare Pages への公開

いずれかの方法を選択する。

- **GitHub リポジトリに接続する**：Cloudflare ダッシュボード → Workers & Pages → 作成 → Pages → Git に接続 の順に進み、本リポジトリを選択する。Root directory（ルートディレクトリ）には `03-tool` を、ビルドコマンドには `mkdir -p _site && cp -r index.html _headers assets data vendor offline _site/` を、出力ディレクトリには `_site` を入力する。以降はプッシュのたびに自動で公開される。
- **コマンドラインから直接アップロードする**（Git 連携は不要）：`03-tool/` ディレクトリで上記のビルドコマンドを実行し、続けて `npx wrangler pages deploy _site --project-name agent-baseline-assessor` を実行する。

公開後のアドレスは `https://<プロジェクト名>.pages.dev` となる。独自ドメインを割り当てることも可能である。社内のみからアクセスさせたい場合は、さらに Cloudflare Access を設定し、企業メールまたは IdP でのログインを必須とすることができる。

## 5、データとプライバシー

- 評価データはブラウザの localStorage に保存され、アップロードされない。オンライン版はページ、画像、フォントなどの静的リソースのみを読み込み、統計や遠隔測定のコードを含まない。
- ローカルストレージはディレクトリではなくオリジン単位で分離される。`security.teloa.ai` 配下のプロジェクトは同じオリジンを共有し、GitHub Pages の `<アカウント>.github.io` も同様である。同じオリジンの他のページはデータを読み取れる。Chrome の file:// ページもストレージを共有する場合がある。機密性の高い評価には専用ドメインまたは私有化デプロイを利用すること。
- 旧 GitHub Pages アドレスから新ドメインへ移動しても、評価データは自動移行されない。旧アドレスで JSON をエクスポートし、新アドレスでインポートすること。
- PC の買い替え、ブラウザのクリーンアップ、または他者によるレビューを依頼する前に、「データ」画面で JSON をエクスポートすること。
- ファイルのインポート時には、ベースラインに存在する番号と既知の状態値のみを受け付け、それ以外の内容はすべて無視する。表示されるテキストはすべて、エスケープしてから描画される。

## 6、言語

ページは 简体中文、English、日本語、한국어、Deutsch、Français、Español に対応し、右上で切り替える。切り替えても入力済みの評価には影響しない。初回は英語で表示され、手動で選択した言語は保存される、アドレスの末尾に `?lang=ja`（または `zh-CN`、`en`、`ko`、`de`、`fr`、`es`）を付けると指定した言語で開く。エクスポートした Excel は表示中の言語で作成され、どの言語でエクスポートしたファイルもインポートできる。`offline/` 配下の標準オフライン評価表は英語版である。他の言語では「データ」ページの「空白の評価表をダウンロード」を使う。

中国語のオフライン評価表: [baseline-assessment.zh-CN.xlsx](../../03-tool/offline/baseline-assessment.zh-CN.xlsx).
