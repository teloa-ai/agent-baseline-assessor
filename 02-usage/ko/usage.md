# 02 사용 방법

이 문서는 자가 평가 도구로 기준선에 대해 평가하는 방법을 설명합니다. 온라인, 오프라인, 사내(프라이빗) 배포의 세 가지 사용 방식과 채점 규칙, 데이터 저장 방식을 다룹니다. 도구 자체의 디렉터리 구조와 유지보수 방법은 [03 도구](../../03-tool/docs/ko.md)를 참고하십시오.

## 평가 예시

아래 화면(영어)은 포함된 모의 데이터로 생성했습니다. Teloa나 실제 플랫폼의 평가가 아닙니다.

![모의 성숙도 보고서(영어): L1 달성, 목표 L2, 충족률 약 79%, 차이 47개](../assets/maturity-report.en.png)

L1 요구사항 90개를 모두 충족합니다. L2 추가 요구사항 137개 중 충족 90개, 부분 충족 20개, 미충족 17개, 미평가 10개입니다. 목표 범위에서는 180 / 227개로 79%가 표시되며, L2까지 47개가 남습니다. L3 13개는 미평가이며 목표 L2 충족률에 포함하지 않습니다.

![모의 적용 범위 매트릭스 일부(영어)](../assets/coverage-matrix.en.png)

### 화면 재현하기

1. [예시 평가 JSON](../examples/demo-assessment.json)을 내려받습니다.
2. 도구의 데이터 페이지에서 파일을 가져옵니다. 현재 평가를 교체하므로 기존 데이터는 먼저 JSON으로 내보냅니다.
3. 평가 보고서에서 성숙도와 차트를 확인하고 적용 범위 매트릭스에서 차이를 찾습니다.

## 1. 세 가지 사용 방식

### 1.1 온라인

GitHub Pages 또는 Cloudflare Pages에 게시할 수 있으며, 두 서비스 모두 무료 요금제가 있습니다. 절차는 4절을 참고하십시오. Cloudflare Pages는 `03-tool/` 아래의 `_headers`를 읽어 nginx 설정과 동일한 보안 응답 헤더를 적용합니다. GitHub Pages는 사용자 정의 응답 헤더를 지원하지 않습니다.

### 1.2 오프라인

두 가지 방법이 있습니다.

- **오프라인 웹페이지**: 저장소 zip을 내려받아 압축을 풀고 `03-tool/index.html`을 더블클릭하면 바로 사용할 수 있습니다. 기능은 온라인 버전과 완전히 같습니다.
- **오프라인 Excel**: `03-tool/offline/baseline-assessment.xlsx`를 직접 작성합니다. 표에는 드롭다운 선택 항목, 요약 수식, 차이 통계가 포함되어 있으며, 작성이 끝나면 웹페이지로 다시 가져와 평가를 이어갈 수 있습니다.

### 1.3 사내(프라이빗) 배포

페이지는 순수 정적 파일이므로 어떤 정적 파일 서버에서든 호스팅할 수 있습니다. 저장소에는 root가 아닌 사용자로 실행되는 nginx 이미지 설정이 포함되어 있으며, 콘텐츠 보안 정책(CSP)으로 페이지가 외부 주소에 연결하는 것을 금지합니다.

```bash
cd 03-tool && docker build -f deploy/Dockerfile -t agent-baseline-assessor .
docker run -d -p 8080:8080 --read-only --tmpfs /tmp agent-baseline-assessor
```

Docker를 사용하지 않는 경우에는 `03-tool/` 아래의 `index.html`, `assets/`, `data/`, `vendor/`, `offline/`을 웹 루트에 복사하면 됩니다. `deploy/nginx.conf`의 보안 응답 헤더를 함께 적용하는 것을 권장합니다. MIME 타입은 nginx에 기본 포함된 `mime.types`를 그대로 사용하십시오. server 블록에 `types {}`를 따로 작성하면 전체 테이블이 덮어써져 페이지가 파일로 다운로드되므로 주의하십시오.

## 2. 기능

| 페이지 | 기능 |
| --- | --- |
| 적용 범위 매트릭스 | 상단에 현재 달성 등급과 L1, L2, L3 각 등급의 달성 현황이 표시됩니다. 장별로 볼 때는 행마다 한 장, 칸마다 한 절이며, 칸 하단의 구간별 색상 막대가 항목별 상태를 하나씩 보여 줍니다. 「적용 컴포넌트 × 장」으로 전환하면 각 적용 컴포넌트가 장마다 얼마나 충족되는지 보여 주는 히트맵이 나타납니다. 칸을 클릭하면 항목별 평가를 시작할 수 있습니다 |
| 항목별 평가 | 장, 컴포넌트, 등급, 상태, 키워드로 필터링하고, 상태를 표시하며, 증거, 담당자, 완료 예정일을 입력합니다. 해당되지 않는 절은 절 단위로 한꺼번에 해당 없음으로 표시할 수 있습니다 |
| 평가 보고서 | 결론을 먼저 제시합니다. 성숙도 단계, 다음 등급까지 남은 항목 수, 목표 등급 내 충족률, 차이 항목, 평가 진행률을 보여 준 뒤 우선 처리할 요구사항을 나열합니다. 차트에는 충족률 레이더(장별 또는 컴포넌트별), 장별 성숙도, 차이 분포가 있으며, 모두 PNG 또는 SVG로 내려받을 수 있습니다. 그 밖에 컴포넌트별 통계표와 전체 차이 목록이 함께 제공됩니다 |
| 데이터 | 평가 정보를 입력합니다. JSON 또는 Excel로 내보내고, JSON 또는 오프라인 Excel을 가져오며, 이전 결과를 불러와 비교하고, 현재 평가를 초기화합니다 |

내보낸 Excel은 오프라인 템플릿과 구조가 같으며, 평가표, 요약, 차이 목록, 아키텍처 관점, 설명의 다섯 시트로 구성됩니다. 요약 시트의 수식은 상태에 따라 실시간으로 계산되고, 목표 등급은 드롭다운으로 전환할 수 있습니다.

## 3. 채점 규칙

- **충족률** = 충족된 항목 ÷ 적용 요구사항. 목표 등급 내의 요구사항만 집계합니다. 부분 충족과 미평가는 모두 미충족으로 계산합니다.
- **특정 등급 달성**: 해당 등급 이하의 모든 적용 요구사항이 충족되어야 달성으로 봅니다. 하나라도 빠지면 그 전 등급에 머무릅니다.
- **차이 항목**: 목표 등급 내에 있고, 적용 대상이며, 아직 충족되지 않은 요구사항입니다.
- **해당 없음**: 플랫폼이 어떤 기능을 갖추지 않은 경우(예: MCP를 지원하지 않는 경우), 해당 절 전체를 해당 없음으로 표시합니다. 해당 없음 항목은 충족률 계산에서 제외됩니다.

웹페이지와 Excel은 같은 규칙을 사용합니다. Excel에서 상태를 비우거나 드롭다운 이외의 값을 입력하면 미평가로 계산됩니다.

## 4. 배포

### 4.1 GitHub Pages에 배포

1. 새 저장소를 만들고 프로젝트 전체를 `main` 브랜치에 푸시합니다. 워크플로가 자동으로 `03-tool/`에 들어가 빌드합니다.
2. 저장소의 Settings → Pages → Build and deployment에서 Source를 **GitHub Actions**로 선택합니다.
3. 이후 `main`에 푸시할 때마다 `.github/workflows/pages.yml`이 오프라인 평가표를 다시 생성하고 자체 점검을 실행한 다음, 페이지에 필요한 파일만 배포합니다. 빌드 작업은 읽기 권한만 가지며, 의존성을 설치할 때 설치 스크립트를 실행하지 않습니다. 배포 작업은 제3자 코드를 전혀 실행하지 않습니다.

GitHub 무료 계정은 공개 저장소에서만 Pages를 사용할 수 있습니다. 기준선을 아직 공개할 수 없다면 사내 배포를 사용하거나, 비공개 Pages를 지원하는 GitHub Enterprise를 이용하십시오.

### 4.2 Cloudflare Pages에 배포

다음 중 한 가지 방법을 선택합니다.

- **GitHub 저장소 연결**: Cloudflare 콘솔 → Workers & Pages → 생성 → Pages → Git 연결에서 이 저장소를 선택합니다. Root directory(루트 디렉터리)에는 `03-tool`, 빌드 명령에는 `mkdir -p _site && cp -r index.html _headers assets data vendor offline _site/`, 출력 디렉터리에는 `_site`를 입력합니다. 이후 푸시할 때마다 자동으로 배포됩니다.
- **명령줄에서 직접 업로드**(Git 연동 불필요): `03-tool/` 디렉터리에서 위의 빌드 명령을 실행한 뒤 `npx wrangler pages deploy _site --project-name agent-baseline-assessor`를 실행합니다.

배포된 주소는 `https://<프로젝트 이름>.pages.dev`이며, 자체 도메인을 연결할 수도 있습니다. 회사 내부에서만 접근하게 하려면 Cloudflare Access를 추가로 적용하여 기업 이메일 또는 IdP로 먼저 로그인하도록 요구할 수 있습니다.

## 5. 데이터와 개인정보

- 평가 데이터는 브라우저의 로컬 스토리지(localStorage)에 저장됩니다. 페이지는 어떠한 네트워크 요청도 보내지 않으며, 통계나 텔레메트리 코드도 포함하지 않습니다.
- 로컬 스토리지는 출처(origin) 단위로 격리됩니다. GitHub Pages의 프로젝트 페이지는 `<계정>.github.io`라는 출처를 공유하므로, 같은 계정의 다른 페이지가 이 데이터를 읽을 수 있습니다. Chrome에서 file://로 연 로컬 웹페이지도 같은 저장소를 공유합니다. 평가 내용이 민감하다면 독립된 도메인을 쓰거나 사내 배포를 사용하십시오.
- 컴퓨터를 바꾸거나, 브라우저 데이터를 정리하거나, 다른 사람에게 검토를 맡기기 전에 먼저 「데이터」 페이지에서 JSON을 내보내십시오.
- 파일을 가져올 때는 기준선에 존재하는 번호와 알려진 상태 값만 허용하며, 그 밖의 내용은 모두 무시합니다. 표시되는 모든 텍스트는 렌더링하기 전에 이스케이프 처리됩니다.

## 6. 언어

페이지는 简体中文, English, 日本語, 한국어, Deutsch, Français, Español을 지원하며, 오른쪽 위에서 전환합니다. 전환해도 이미 입력한 평가에는 영향이 없습니다. 처음 열 때는 브라우저 언어 설정을 따르며, 주소 끝에 `?lang=ko`(또는 `zh-CN`, `en`, `ja`, `de`, `fr`, `es`)를 붙이면 지정한 언어로 열립니다. 내보낸 Excel은 현재 언어로 작성되며, 어느 언어로 내보낸 파일이든 가져올 수 있습니다. `offline/` 아래의 오프라인 평가표는 중국어판입니다. 다른 언어로는 「데이터」 페이지의 「빈 평가표 다운로드」를 사용하십시오.
